# 03 - WINDOWS LAPTOP SETUP

This guide prepares a Windows laptop to run the restaurant system. Treat it as a new
installation or standby server, not as a second live database. Only one server should
accept orders at a time; see [05.3-SYNC_BETWEEN_DEVICES.md](05.3-SYNC_BETWEEN_DEVICES.md).

## Setup sequence

1. Install required software using
   [03.1-SOFTWARE_INSTALLATION.md](03.1-SOFTWARE_INSTALLATION.md).
2. Connect and test the printer using
   [03.2-PRINTER_SETUP.md](03.2-PRINTER_SETUP.md).
3. Create a laptop-specific backend configuration using
   [03.3-ENVIRONMENT_CONFIG.md](03.3-ENVIRONMENT_CONFIG.md).
4. If migrating existing restaurant data, restore a verified backup as described in
   [05.2-RESTORE_PROCEDURES.md](05.2-RESTORE_PROCEDURES.md). Do not copy a live SQLite
   database or overwrite the laptop's `.env` blindly.
5. Start the app with
   [`START_DRAGONFLY_GARDEN.bat`](../Start%20the%20app%20in%20deployment%20form/Pc/START_DRAGONFLY_GARDEN.bat).
   The backend runs in the background; no command window needs to stay open.

Open `http://localhost:5000` on the laptop. Other devices on the same trusted network
need the laptop's current LAN IP, not `localhost`; Windows Firewall may need a narrowly
scoped rule for the trusted private network.

The database is stored at
`restaurant-system\backend\src\database\database.sqlite`. The app uses that fixed path;
`DATABASE_PATH` is not a supported setting. The `frontend\dist` folder is generated by
the frontend build and should not be used as the data backup.

Continue with [03.1-SOFTWARE_INSTALLATION.md](03.1-SOFTWARE_INSTALLATION.md).

Closing a browser does not stop the backend. To stop it for all devices, sign in as
manager and choose **Settings → Server control → Stop backend for everyone**. Start it
again by opening a role shortcut or running the launcher.
