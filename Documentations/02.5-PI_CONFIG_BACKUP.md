# 02.5 - RASPBERRY PI CONFIGURATION BACKUP

Do not copy the SQLite database while the application is running. The app can have
uncheckpointed changes in SQLite's write-ahead log. Use the backup process in
[05.1-BACKUP_PROCEDURES.md](05.1-BACKUP_PROCEDURES.md), which requires the server to be
stopped for a manual file backup.

The application data paths are:

- Database: `restaurant-system/backend/src/database/database.sqlite`
- Menu and feedback images: `frontend/public/menu-images/` and
  `frontend/public/feedback-images/`
- Private configuration: `restaurant-system/backend/.env` and optional `.env.local`
- Logs: `restaurant-system/backend/logs/`

The systemd unit is separate from application data. Record its reviewed contents with:

```bash
sudo systemctl cat dragonfly-garden
```

Do not assume it uses `/home/pi`, `/usr/bin/node`, or the same account on another Pi.
Recreate or review it for the target machine using
[02.4-SYSTEMD_SERVICES.md](02.4-SYSTEMD_SERVICES.md).

For recovery, use [05.2-RESTORE_PROCEDURES.md](05.2-RESTORE_PROCEDURES.md). Never extract
an archive over the live project or replace another machine's `.env` without reviewing
its values.
