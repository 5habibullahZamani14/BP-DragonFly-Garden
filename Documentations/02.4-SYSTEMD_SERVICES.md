# 02.4 - START THE BACKEND AUTOMATICALLY WITH SYSTEMD

This guide is for a Raspberry Pi or Linux server using systemd. It configures the Node.js
backend to start at boot and restart after an unexpected failure. It does not configure
the Wi-Fi hotspot or printer; see [02.2-NETWORK_HOTSPOT.md](02.2-NETWORK_HOTSPOT.md)
and [02.3-PRINTER_SETUP.md](02.3-PRINTER_SETUP.md).

## Before you begin

1. Install the project and backend dependencies using
   [03.1-SOFTWARE_INSTALLATION.md](03.1-SOFTWARE_INSTALLATION.md).
2. Create and verify `restaurant-system/backend/.env` as described in
   [03.3-ENVIRONMENT_CONFIG.md](03.3-ENVIRONMENT_CONFIG.md).
3. Check that the Node.js executable is available:

   ```bash
   node --version
   command -v node
   ```

   The deployed app requires Node.js 20 or newer. Use the actual executable path reported
   by `command -v node` below; do not assume it is `/usr/bin/node`.
4. Find your Linux account and project location:

   ```bash
   whoami
   realpath restaurant-system/backend
   ```

   Run the second command from the project root. The account must own or be able to read
   the project and write the database/log locations used by the app.

## Create the service

Open a new service file:

```bash
sudo nano /etc/systemd/system/dragonfly-garden.service
```

Paste this template and replace each angle-bracket value with the real value from the
commands above. Do not leave the angle brackets in the file:

```ini
[Unit]
Description=Dragonfly Garden Backend
Wants=network-online.target
After=network-online.target

[Service]
Type=simple
User=<LINUX_USERNAME>
WorkingDirectory=<ABSOLUTE_PROJECT_PATH>/restaurant-system/backend
ExecStart=<ABSOLUTE_NODE_PATH> src/server.js
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

Save in nano with `Ctrl+O`, Enter, then `Ctrl+X`. The backend loads `.env` from its
working directory; systemd's `EnvironmentFile` is not needed for this application.

## Enable and verify

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now dragonfly-garden.service
sudo systemctl status dragonfly-garden.service --no-pager
```

`active (running)` means the Node process is running, not that every feature, database,
network, or printer is healthy. Check the HTTP health endpoint locally:

```bash
curl -i http://127.0.0.1:5000/health
```

Then open `http://10.42.0.1:5000` from a device connected to the configured hotspot, or
use the server's actual LAN IP. The hotspot must be separately configured and available.

## Useful commands

```bash
sudo systemctl start dragonfly-garden
sudo systemctl stop dragonfly-garden
sudo systemctl restart dragonfly-garden
sudo systemctl status dragonfly-garden --no-pager
sudo journalctl -u dragonfly-garden -n 100 --no-pager
sudo journalctl -u dragonfly-garden -f
```

## Troubleshooting

- **Service fails immediately:** run `sudo journalctl -u dragonfly-garden -n 100
  --no-pager`; check `User`, `WorkingDirectory`, `ExecStart`, dependencies, and `.env`.
- **Node works in a terminal but not systemd:** the service must use the absolute Node
  executable path. Version-manager installations may depend on shell initialization and
  may not be suitable for a system service.
- **Port 5000 is already in use:** identify the process before stopping it:
  `sudo ss -ltnp 'sport = :5000'`.
- **Printer does not print:** first verify printing from the OS queue; systemd status does
  not test printer output.

Do not copy this unit to another machine without changing the user, paths, and Node
executable to match that machine.
