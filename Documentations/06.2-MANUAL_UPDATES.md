# 06.2 - UPDATE FROM A TRUSTED OFFLINE RELEASE

Use this procedure only when Git/network access is unavailable and the project maintainer
has provided a complete, trusted release archive. Do not update by copying a handful of
source files from email or a chat.

## Before replacing code

1. Back up the database, images, and configuration using
   [05.1-BACKUP_PROCEDURES.md](05.1-BACKUP_PROCEDURES.md).
2. Stop the application and confirm it is no longer accepting orders.
3. Extract the release to a new temporary folder and confirm it contains the complete
   project, including both `package.json` files and lockfiles.
4. Keep the current project until the new version has passed verification.

## Install and build

Copy the release code over the existing code while explicitly preserving machine data:

- Keep `restaurant-system/backend/.env` and `.env.local`.
- Keep `restaurant-system/backend/src/database/database.sqlite`.
- Keep existing menu/feedback images and uploads unless the release specifically contains
  a reviewed migration for them.
- Do not copy a release's `node_modules`; install dependencies from the lockfiles.

From the project root, run:

```text
cd restaurant-system/backend
npm ci
cd ../../frontend
npm ci
npm run build
```

If the release does not include lockfiles, stop and ask the maintainer for a complete
release; do not guess dependency versions with `npm install`.

## Start and verify

- Raspberry Pi: `sudo systemctl start dragonfly-garden`, then check
  `sudo systemctl status dragonfly-garden --no-pager`.
- Windows laptop: use
  [`START_DRAGONFLY_GARDEN.bat`](../Start%20the%20app%20in%20deployment%20form/Pc/START_DRAGONFLY_GARDEN.bat).

Check `http://127.0.0.1:5000/health`, log in, verify existing data, and print a test
receipt before returning to service. If any step fails, stop and restore the preserved
code/data rather than repeatedly overwriting files.

For regular updates through Git, use [06.1-GITHUB_UPDATES.md](06.1-GITHUB_UPDATES.md).
