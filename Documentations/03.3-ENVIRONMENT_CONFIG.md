# 03.3 - ENVIRONMENT CONFIGURATION (WINDOWS LAPTOP)

The backend needs a private `.env` file for its runtime configuration. Do not commit it,
send it by email, or put it in a public/shared folder.

## 1. Create the local configuration

1. In `restaurant-system\backend`, copy `.env.example` to `.env`.
2. Open `.env` in a text editor and replace the `JWT_SECRET` placeholder with a newly
   generated random value. In Command Prompt or PowerShell, run:

   ```text
   node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
   ```

3. Leave optional integrations such as `RESEND_API_KEY` and `GROQ_API_KEY` blank if they
   are not configured. Do not paste credentials into chat, source code, or a GitHub file.

The backend loads `.env.local` after `.env` and lets `.env.local` override it. For a clean
installation, use `.env` only; if `.env.local` already exists, check it locally because it
may override the settings you just configured.

## 2. Preserve or start fresh data

The live database is `restaurant-system\backend\src\database\database.sqlite`. A first
startup creates/initializes the database when needed. To migrate existing restaurant data,
use the documented backup/restore procedure and restore a verified database backup while
the application is stopped. Do not copy a live SQLite database while the server is using
it, and do not replace the database if you intend to start with a clean one.

The example `.env` does not select a database path; SQLite is stored at the path above.

## 3. Start and check the application

From the project folder, double-click
[`START_DRAGONFLY_GARDEN.bat`](../Start%20the%20app%20in%20deployment%20form/Pc/START_DRAGONFLY_GARDEN.bat).
The launcher requires Node.js 20 LTS or newer. It installs missing dependencies, builds
the frontend, starts the backend in the background, checks `/ready`, and opens the
manager view when ready. When a fresh start is needed, a browser page shows startup
progress and automatically opens the manager view when the backend is ready. The
Manager, Employee, and Customer desktop shortcuts can be created by running
`CREATE_APP_SHORTCUTS.bat` from the repository root.

Closing the browser does not stop the backend. To stop it for all devices, sign in as
manager and choose **Settings → Server control → Stop backend for everyone**. To start
it again, open a role shortcut or run the launcher.

If the server or network connection is interrupted while a role page is open, the app
shows a connection notice and retries automatically. Keep the page open; do not refresh
or repeat an order or payment until the connection returns and you have confirmed
whether the first attempt succeeded. A live-updates warning means the server is
reachable but real-time updates are still reconnecting.

Open `http://localhost:5000` on the laptop. For phones/tablets on the same Wi-Fi network,
use the laptop's LAN address on port `5000`; allow that port through Windows Firewall only
on the trusted restaurant network.

## Troubleshooting

- **JWT secret missing:** check that `restaurant-system\backend\.env` exists and has a
  non-placeholder `JWT_SECRET`.
- **Port 5000 already in use:** close the other server or investigate which application
  owns the port before changing the app port.
- **Only an API message appears, not the app:** build the frontend with `npm run build`
  from the `frontend` folder, or restart using the deployment launcher.
- **Password reset email unavailable:** this optional feature needs a valid
  `RESEND_API_KEY`; ordinary local ordering and management do not depend on it.

For data migration and recovery, use [05-DISASTER_RECOVERY.md](05-DISASTER_RECOVERY.md).
