# 05.3 - USING THE SYSTEM ON MORE THAN ONE DEVICE

Do not keep multiple live copies of the restaurant database synchronized by copying
`database.sqlite`. SQLite files can have active write-ahead-log files, and two devices
that accept orders create independent, conflicting histories. Copying one database over
another can lose orders or corrupt data.

## Recommended arrangement

Use one active server and connect all ordering devices to it over the trusted restaurant
network. Treat the other computer as a standby only:

1. Keep the standby's application code updated separately.
2. Create a verified backup from the active server using
   [05.1-BACKUP_PROCEDURES.md](05.1-BACKUP_PROCEDURES.md).
3. If you must switch servers, stop the old server first so only one machine can accept
   orders.
4. Restore a selected backup to the standby using
   [05.2-RESTORE_PROCEDURES.md](05.2-RESTORE_PROCEDURES.md).
5. Configure a machine-specific `.env`, printer queue, network address, and startup
   service. Test before taking orders.
6. If the old server becomes available again, do not run both servers as active systems.
   Decide which database is authoritative before switching back.

## What can be copied

- **Application code:** use the project's Git repository or a trusted release archive.
- **Restaurant data:** use a verified backup/restore procedure, with the server stopped
  during direct file operations.
- **Images:** restore from the same data backup; do not assume copying the database alone
  also copies image files.
- **Environment configuration:** create and review separately on each host. It contains
  secrets and may include host-specific settings; do not copy it casually.
- **Printer and network setup:** configure and test separately on each device.

Do not use the former sync commands in this guide's earlier versions. They copied a live
SQLite file, overwrote destination data without a recovery point, and could delete
temporary files shared with other work. There is no supported automatic multi-device
database synchronization feature.
