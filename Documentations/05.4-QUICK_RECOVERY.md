# 05.4 - QUICK RECOVERY CHECKLIST

Use this checklist to identify the next safe step. A running service does not guarantee
that the database, network, or printer is ready.

## Raspberry Pi service is unavailable

1. Check power, SD card, and network.
2. On the Pi, run:

   ```bash
   sudo systemctl status dragonfly-garden --no-pager
   sudo journalctl -u dragonfly-garden -n 100 --no-pager
   ```

3. If the service is stopped and there is no data/storage error, start it:

   ```bash
   sudo systemctl start dragonfly-garden
   curl -i http://127.0.0.1:5000/health
   ```

4. If it still fails, save the error output. Do not repeatedly restart or overwrite files;
   proceed with [05.2-RESTORE_PROCEDURES.md](05.2-RESTORE_PROCEDURES.md).

## Switch temporarily to the Windows laptop

1. Stop the Pi or otherwise ensure it cannot accept orders.
2. Install and start the laptop using [03-LAPTOP_SETUP_GUIDE.md](03-LAPTOP_SETUP_GUIDE.md).
3. If the laptop needs existing restaurant data, restore a verified backup before taking
   orders. Do not copy the active database while the Pi server is running.
4. Connect and test the printer on the laptop. Windows printer queues are configured
   separately from Linux queues.
5. Open `http://localhost:5000` on the laptop. Other devices must use the laptop's LAN IP.
6. Confirm the menu, employees, settings, and test receipt before resuming service.

## Printer does not print

- Check power, paper, cable/network connection, and the OS printer queue.
- On Linux, run `lpstat -p` and test the CUPS queue.
- On Windows, print a Windows test page and check the queue.
- In the manager dashboard, discover/select the correct printer and submit a test print.
- A reported job submission does not prove physical output. Verify the receipt and cutter
  separately; see [04-PRINTER_TROUBLESHOOTING.md](04-PRINTER_TROUBLESHOOTING.md).

## Do not use the legacy cloud restore command

Do not run `node src/restoreBackup.js` or the old emergency restore scripts. They are
incompatible with current encrypted archive backups and can damage the database. Use the
manager dashboard restore flow when available, or get help with a verified local archive.
