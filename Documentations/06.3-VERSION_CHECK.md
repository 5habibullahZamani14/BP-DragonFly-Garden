# 06.3 - CHECK THE CODE VERSION

This compares Git commits; it does not check the database, printer, or whether the app is
healthy.

## Manager dashboard

Open **Settings → System Updates** and choose **Check for Updates**. The manager view
shows the installed application version, configured update branch, and shortened local
and remote commit IDs. It also indicates whether the update is eligible for the safe
in-app updater and explains why an available update may be blocked.

The updater checks the configured `origin` branch (`UPDATE_BRANCH`, or `main` if unset).
It allows an update only when the installed branch is clean and the remote commit is a
fast-forward that does not change backend dependency manifests. A different commit ID
alone does not prove that the remote version is newer or safe to deploy.

## In a terminal

From the project root:

```text
git status --short
git branch --show-current
git rev-parse --short HEAD
git fetch origin
git rev-parse --short origin/main
```

The final command only compares correctly if `main` is the intended deployment branch.
If the installation uses `UPDATE_BRANCH`, compare its corresponding `origin/<branch>`.
Different commit IDs mean the checked-out code and remote reference differ; that does not
by itself prove that the remote commit is newer or safe to deploy.

Before updating, confirm the worktree is clean, the branch and remote are correct, and a
backup exists. Follow [06.1-GITHUB_UPDATES.md](06.1-GITHUB_UPDATES.md). Never use a hard
reset to force the versions to match.
