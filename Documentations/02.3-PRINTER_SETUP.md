# 02.3 - PRINTER SETUP (RASPBERRY PI / LINUX)

The application submits Linux print jobs with the `lp` command to an installed CUPS queue.
The printer must first work in the operating system. A successful app response means CUPS
accepted the job; it does not prove that paper printed or was cut.

## 1. Install and check CUPS

On a Debian-based Raspberry Pi OS image:

```bash
sudo apt update
sudo apt install cups cups-client
sudo systemctl enable --now cups
lpstat -r
```

If CUPS is not available in the installed OS or another print service is in use, stop and
confirm the supported printer setup before switching services.

## 2. Add and test the printer

Connect and power on the printer. Add it with the CUPS administration interface at
`http://localhost:631` or the OS printer settings. Select a driver/queue compatible with
the actual printer and receipt paper. Then check the queue and send a simple operating
system test:

```bash
lpstat -p
lpstat -d
printf 'Printer test\n' | lp -d 'EXACT_QUEUE_NAME'
```

Replace `EXACT_QUEUE_NAME` with the queue name from `lpstat -p`. Do not assume the USB
device will be named `YHD-8390`; its CUPS queue name is configured separately.

## 3. Select and test the queue in the application

1. Start the backend and open the manager dashboard.
2. Open **Settings → Printer Management** and choose **Discover Printers**.
3. Discovery lists installed CUPS queues only. Select the exact queue and save it as the
   active/default printer.
4. Choose **Test Print** and check both the app result and the physical receipt.

On Linux, this application path sends plain text to the selected CUPS queue with `lp`. The
app does not set paper width or send ESC/POS cutter commands. Configure the queue for the
installed printer and verify the actual text layout and cutter behavior separately before
service.

If a job appears under **Print Jobs Needing Review**, inspect the CUPS queue and physical
printer before arranging a manual reprint. The application does not retry these jobs
automatically because the original may already have printed.

## Troubleshooting

- **No queue appears:** check `sudo systemctl status cups`, `lpstat -p`, and USB detection
  with `lsusb`; restart the backend after adding a queue.
- **Job accepted but no paper:** inspect the queue with `lpstat -W not-completed -o`,
  confirm the printer is online, and try the OS test print.
- **Text is garbled or width is wrong:** check the CUPS queue/driver and paper size. Use a
  queue compatible with the plain-text output; do not assume ESC/POS commands are sent.
- **Cutter does not operate:** the app does not send a cut command. Do not rely on an app
  test response as proof of cutting.
