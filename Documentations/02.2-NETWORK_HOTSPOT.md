# 02.2 - RASPBERRY PI WI-FI HOTSPOT

This guide configures a Raspberry Pi OS installation that uses NetworkManager. The
Pi's Wi-Fi adapter must support access-point mode. This creates a local network; it
does not provide internet access to customers unless a separate upstream connection is
configured.

The application defaults to `http://10.42.0.1:5000` for captive-portal checks, but
phones do not reliably open the application automatically. Customers should scan a table
QR code or browse directly to the system URL.

## 1. Check NetworkManager and Wi-Fi

Open a terminal on the Pi and run:

```bash
nmcli --version
nmcli device status
nmcli -f WIFI-PROPERTIES.AP device show wlan0
```

Use the Wi-Fi interface name shown by `nmcli device status` in place of `wlan0` if it is
different. If NetworkManager is missing, install it only after confirming that it is the
network manager for this OS image; installing or switching network managers can disconnect
the Pi.

## 2. Create the access point

Replace `wlan0` with the Wi-Fi interface name from the previous step. Create the
connection first; NetworkManager may generate a temporary password:

```bash
sudo nmcli device wifi hotspot ifname wlan0 con-name DragonflyHotspot ssid DragonflyHotspot
```

Set a unique Wi-Fi password of at least eight characters without putting it in shell
history:

```bash
read -rsp 'Choose a private Wi-Fi password: ' WIFI_PASSWORD
printf '\n'
sudo nmcli connection modify DragonflyHotspot wifi-sec.psk "$WIFI_PASSWORD"
unset WIFI_PASSWORD
```

Then configure and activate the connection:

```bash
sudo nmcli connection modify DragonflyHotspot ipv4.method shared ipv4.addresses 10.42.0.1/24 connection.autoconnect yes
sudo nmcli connection up DragonflyHotspot
```

NetworkManager's `ipv4.method shared` provides address sharing/NAT if upstream networking
is configured. Confirm the connection and address:

```bash
nmcli connection show DragonflyHotspot
ip -4 address show wlan0
```

If a connection with that name already exists, inspect it before changing it. The hotspot
command may change which Wi-Fi network the Pi uses.

## 3. Check access from another device

1. Connect a phone to `DragonflyHotspot` using the private password you selected.
2. Open `http://10.42.0.1:5000` in the phone's browser.
3. If the page does not load, check the backend service with
   `sudo systemctl status dragonfly-garden` and verify the Pi has address `10.42.0.1`.

The application server must already be installed, configured with a valid backend
`.env` (including `JWT_SECRET`), built, and running. See
[02.4-SYSTEMD_SERVICES.md](02.4-SYSTEMD_SERVICES.md).

## 4. Start the hotspot on boot

The `connection.autoconnect yes` setting asks NetworkManager to reactivate the saved
connection after boot when the Wi-Fi device is available. Verify this after reboot:

```bash
nmcli connection show DragonflyHotspot
nmcli device status
```

Do not run `systemctl enable NetworkManager` as a substitute for configuring the saved
connection; NetworkManager is normally managed by the OS image.

## Troubleshooting

- **Hotspot is not listed:** confirm the Wi-Fi adapter supports access-point mode, check
  `nmcli device status`, and inspect `sudo journalctl -u NetworkManager -n 100`.
- **Phone connects but app does not load:** test `http://10.42.0.1:5000` directly, check
  the backend service and confirm it listens on `0.0.0.0` and port `5000`.
- **Forgot the password:** change the saved connection's Wi-Fi password locally, then
  reconnect devices:

  ```bash
  read -rsp 'Choose a new private Wi-Fi password: ' WIFI_PASSWORD
  printf '\n'
  sudo nmcli connection modify DragonflyHotspot wifi-sec.psk "$WIFI_PASSWORD"
  unset WIFI_PASSWORD
  sudo nmcli connection down DragonflyHotspot
  sudo nmcli connection up DragonflyHotspot
  ```

- **Need to use a router instead:** connect the Pi and clients to that trusted network,
  find the Pi's current address, and use that address in the table QR codes. Do not assume
  it remains `10.42.0.1`.
