# 06.1 - UPDATE FROM THE PROJECT'S GIT REPOSITORY

An update changes application code. It should not replace the restaurant database or
machine-specific configuration. Back up the data first and do not update during service.

## Important safety notice

The manager dashboard's **Check for Updates** action can check the remote version. Do not
click **Update Now** on a production machine: the current server-side updater runs
`git reset --hard origin/main`, which can discard local changes, and it does not reliably
restart the running service. Use the controlled procedure below instead.

## Before updating

1. Make and verify a backup using [05.1-BACKUP_PROCEDURES.md](05.1-BACKUP_PROCEDURES.md).
2. Stop taking orders and stop the backend:
   - Raspberry Pi: `sudo systemctl stop dragonfly-garden`
   - Windows: press `Ctrl+C` in the backend console and wait for it to exit.
3. Open a terminal in the project root and check the branch and worktree:

   ```text
   git status --short
   git branch --show-current
   ```

   Continue only if the worktree is clean and you are on the intended deployment branch.
   Do not delete, reset, or overwrite local changes to make it clean.
4. Confirm the Git remote is the expected repository:

   ```text
   git remote -v
   ```

## Update code and dependencies

Run these commands from the project root. They stop if Git cannot safely fast-forward:

```text
git pull --ff-only
```

Then install dependencies from the lockfiles and rebuild:

```text
cd restaurant-system/backend
npm ci
cd ../../frontend
npm ci
npm run build
```

If any command fails, do not continue as though the update succeeded. Keep the error
output and resolve it before restarting.

## Restart and verify

- Raspberry Pi systemd installation:

  ```bash
  sudo systemctl start dragonfly-garden
  sudo systemctl status dragonfly-garden --no-pager
  curl -i http://127.0.0.1:5000/health
  ```

- Windows laptop: run
  [`START_DRAGONFLY_GARDEN.bat`](../Start%20the%20app%20in%20deployment%20form/Pc/START_DRAGONFLY_GARDEN.bat)
  and keep its backend window open.

Before resuming service, log in, inspect the menu and existing data, and print a test
receipt. A running process or HTTP health response does not by itself verify the printer
or all business workflows.

If a failed update needs rollback, stop the server and use a known-good code revision and
verified data backup. Do not use `git reset --hard` on a machine that may contain local
work or production data.
