# 03.2 - PRINTER SETUP (WINDOWS LAPTOP)

This guide covers connecting the restaurant system to a Windows-installed printer.
The application submits Windows print jobs through the selected Windows printer queue.

## 1. Connect and install the printer

1. Connect the printer by USB or add it in Windows using its network address.
2. Turn it on and install the manufacturer's driver if Windows does not install one.
3. Open **Settings → Bluetooth & devices → Printers & scanners** and confirm the printer is listed.
4. Open the printer queue and print a Windows test page. Resolve any Windows or driver errors first.

Printer sharing is not required for the application's Windows print queue. `print_gdi.exe`
is not required for this Windows print path.

## 2. Start the restaurant system

1. Create the backend `.env` file as described in
   [03.3-ENVIRONMENT_CONFIG.md](03.3-ENVIRONMENT_CONFIG.md).
2. From the project folder, run
   [`START_DRAGONFLY_GARDEN.bat`](../Start%20the%20app%20in%20deployment%20form/Pc/START_DRAGONFLY_GARDEN.bat).
   The launcher installs missing dependencies, builds the frontend, starts the backend,
   waits for its health check, and opens the manager view.
3. Log in and open **Settings → Printer Management**.
4. Choose **Discover Printers**, select the Windows queue, save the printer selection, and
   click **Test Print**.

Discovery lists installed Windows print queues only. The app does not set paper width,
feed lines, print delay, or cutter commands. Set paper size and any supported cutter
behavior in the printer's Windows queue/driver settings. The app renders plain text using
a simple font and applies alignment only; Windows and the driver determine its printable
area and how long lines fit.

The Windows print helper reports when the job has been submitted to the Windows queue;
that does not prove paper physically printed. Check the queue and printer if nothing comes
out. Software margins are zero, but a driver or printer can still have unprintable edges.
Verify the actual receipt and cut behavior before relying on it during service.

## Troubleshooting

### Printer is not discovered

- Confirm it appears in Windows **Printers & scanners** and is online.
- Restart the backend after installing a driver, then discover printers again.
- Select the exact queue name shown in Windows.

### Job is accepted but nothing prints

- Check the Windows print queue for paused, offline, or failed jobs.
- Confirm the printer is powered on, loaded with paper, and prints a Windows test page.
- If Windows itself cannot print, resolve the driver or connection issue there first.
- If a job appears under **Print Jobs Needing Review**, inspect the Windows queue and the
  physical printer before arranging a manual reprint. The application does not retry these
  jobs automatically because the original may already have printed.

### Receipt width or cutting is wrong

- Check the printer's driver preferences and paper size.
- Print a Windows test page, then submit another app test ticket.
- Confirm cutter support in the printer's documentation and driver settings, then test it
  physically. The app does not send cutter commands.

For general printer diagnostics, see
[04-PRINTER_TROUBLESHOOTING.md](04-PRINTER_TROUBLESHOOTING.md).
